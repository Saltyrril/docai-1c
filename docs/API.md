# HTTP API сервиса docai

Локальный сервис, через который с системой работает 1С. Запуск и проверка — в конце документа.
Интерактивная страница с теми же методами (Swagger): `http://127.0.0.1:8000/docs`.

## Общие правила

- **Адрес:** только `127.0.0.1` (порт по умолчанию 8000). Заголовок `Host` другого вида отклоняется (400).
- **Формат:** JSON в UTF-8. Все ключи есть в каждом ответе, отсутствующее значение — `null`.
- **Числа — строки с точкой:** суммы, количество, цена, уверенность, секунды — `"2440.00"`, `"0.93"`. Целые технические счётчики (`pages`, `n`, `queue_ahead`, `feedback_count`) — обычные числа JSON.
- **Даты — ISO 8601:** `"2026-11-14"`; метки времени заданий — UTC: `"2026-11-18T10:00:00+00:00"`.
- **Ставка НДС** — строка как в документе: `"22%"`, `"без НДС"`, `"22/122"`.
- **Ошибки:** `{"detail": "текст на русском"}` с кодом HTTP (400, 404, 409, 413, 415, 429). Ошибка разбора тела запроса (422) содержит в `detail` список с описанием.
- **Одно задание за раз:** GPU одна, поэтому задания идут по очереди. Результат нужно опрашивать (`GET /v1/jobs/{id}` раз в 1–2 секунды); документ обрабатывается порядка 15–40 секунд.

## Как это работает

```
1С ── POST /v1/extract (файл) ──────────▶ id задания, status = queued
1С ── GET  /v1/jobs/{id} (опрос) ───────▶ queued → running → done | failed
1С ── GET  /v1/jobs/{id}/preview/1 ─────▶ PNG страницы для формы проверки
1С ── POST /v1/jobs/{id}/feedback ──────▶ значения, которые подтвердил или исправил человек
```

Задания хранятся в SQLite (`data/service/service.db`), файлы и страницы — в `data/service/uploads/<id>/`. Папка `data/` не коммитится. После перезапуска сервиса прерванное задание начинается заново.

## POST /v1/extract

Принять файл и поставить в очередь. Тело — `multipart/form-data`:

| Поле | Тип | Описание |
|---|---|---|
| `file` | файл | PDF, PNG, JPEG или XML (формат ФНС 5.03), до 20 МБ |
| `mode` | строка, необязательно | `auto` (по умолчанию), `text`, `vision`, `ocr` |

Тип файла определяется по содержимому, а не по имени и заголовку `Content-Type`.

```powershell
curl.exe -F "file=@C:\scans\schet.pdf" http://127.0.0.1:8000/v1/extract
```

Ответ `202`:

```json
{"id": "f8afdca55e8c4778be77523f99fbad49", "status": "queued", "queue_ahead": 0}
```

`queue_ahead` — сколько заданий выполняется или ждёт раньше этого.

| Код | Причина |
|---|---|
| 400 | файл пустой |
| 413 | файл больше 20 МБ |
| 415 | не PDF, PNG, JPEG и не XML |
| 422 | неизвестное значение `mode` или нет поля `file` |
| 429 | в очереди уже 50 заданий |

### Состояние задания

| Ключ | Значения |
|---|---|
| `status` | `queued` — ждёт, `running` — выполняется, `done` — готово, `failed` — не удалось (причина в `error`) |
| `queue_ahead` | число заданий впереди; `null`, если задание не ждёт |
| `error` | текст причины при `failed`: Ollama недоступна, файл не подходит под режим, внутренняя ошибка |

### Статус документа

`document_status` — вывод постобработки (D41–D43), по нему 1С решает, что делать:

| Значение | Смысл | Что делает 1С |
|---|---|---|
| `upload` | ошибок нет, уверенность достаточна | можно создавать документ |
| `review` | есть поле с низкой уверенностью или ошибка проверки | показать форму проверки |
| `reject` | документ не собран, нет строк или не прочитана половина полей | отклонить |

`status_reasons` — причины текстом. `document_status_ru` — то же словами для интерфейса.

### Поля

`fields` — все реквизиты документа, включая ячейки таблицы, в порядке схемы. Имя — путь:
`number`, `date`, `seller.inn`, `buyer.kpp`, `seller_bank.bik`, `basis.number`, `totals.vat_amount`, `lines[0].price` (индекс строки с нуля).

| Ключ | Описание |
|---|---|
| `value` | значение строкой; `null` — не найдено |
| `confidence` | уверенность `"0.00"`–`"1.00"` |
| `needs_review` | уверенность ниже порога (по умолчанию 0,8): показать человеку |
| `corrected` | значение исправлено автоматически после модели (см. `corrections`) |

`lines` — те же данные по строкам таблицы, удобные для заполнения табличной части: `n` с 1, девять колонок, `min_confidence` (наименьшая уверенность в ячейках строки) и `needs_review`.

`issues` — ошибки проверок, оставшиеся после автоисправлений: `code` (стабильный, например `INN_CHECKSUM`, `LINE_SUM_MISMATCH`, `FIELD_MISSING`), `severity` (`error` или `warning`), `field`, `message`.
`corrections` — что поменяла постобработка: `kind` (`normalize` — приведение формы записи, `autofix` — исправление суммы), `before`, `after`, `rule`, `reason`.

`doc_type`: `upd`, `bill`, `act`, `torg12`, `vat_invoice`. `upd_status` — `"1"` или `"2"` у УПД, иначе `null`. `route`: `xml`, `text`, `vision`, `ocr` — каким путём извлечено.

| Код | Причина |
|---|---|
| 404 | задания нет |

## GET /v1/jobs/{id}/preview/{page}

Страница документа как `image/png`, номер с 1; длинная сторона 1600 пикселей. Для формы проверки в 1С: рядом со страницей показываются поля с `needs_review`. Число доступных страниц — `preview_pages` (не больше 30). У XML картинок нет (`preview_pages = 0`).

```powershell
curl.exe -o page1.png http://127.0.0.1:8000/v1/jobs/<id>/preview/1
```

| Код | Причина |
|---|---|
| 404 | задания или такой страницы нет |
| 409 | задание ещё не выполнено |

## POST /v1/jobs/{id}/feedback

Значения, которые человек проверил и, возможно, исправил в форме 1С. Это будущие данные для дообучения и метрика «сколько правок». Тело — JSON:

```json
{
  "fields": {
    "number": "00001",
    "seller.inn": "7710140679",
    "totals.amount_with_vat": "2462.06",
    "buyer.kpp": null,
    "lines[0].name": "Скотч упаковочный"
  },
  "author": "Иванов",
  "comment": "проверил по оригиналу"
}
```

- `fields` — имя поля (как в `fields[].name`) → значение; числа строкой с точкой, даты ISO, `null` — человек стёр значение. Присылайте все поля формы, не только изменённые: тогда считается и доля подтверждённых значений. Имя вне схемы допустимо (поле, которого модель не нашла).
- `author`, `comment` — необязательны.

Ответ `200`:

```json
{"job_id": "f8afdca55e8c4778be77523f99fbad49", "feedback_id": 1, "total": 5, "changed": 2}
```

`total` — сколько значений прислано, `changed` — сколько из них отличается от того, что сервис отдал 1С (числа сравниваются как числа: `"10"` = `"10.00"`). Правки можно присылать несколько раз; каждая сохраняется отдельной записью с парами «было → стало».

| Код | Причина |
|---|---|
| 404 | задания нет |
| 409 | задание ещё не выполнено или завершилось ошибкой |
| 422 | имя поля не в формате пути (`seller.inn`, `lines[0].price`), значение не строка, пустой `fields` |

## GET /v1/health

Можно вызывать до загрузки файлов: покажет, готов ли сервис.

```json
{
  "status": "ok",
  "version": "0.1.0",
  "worker_alive": true,
  "queued": 0,
  "running": 0,
  "ollama": {"reachable": true, "model": "qwen3.5:2b-q4_K_M", "model_available": true,
             "model_loaded": false, "error": null},
  "gpu": {"available": true, "vram_total_mib": 4096, "vram_free_mib": 3964, "error": null}
}
```

`status`: `ok` — воркер жив, Ollama отвечает и модель скачана; иначе `degraded` (код ответа всё равно 200, причина — в `ollama.error`). `model_loaded: false` — это нормально: модель загрузится при первом задании, первое извлечение займёт на несколько секунд больше. XML обрабатывается и без Ollama.

## Обмен файлами (способ Б)

Запасной путь, если из 1С нельзя сделать HTTP-запрос (P15, D54). Сервис раз в полсекунды просматривает папку обмена (по умолчанию `data/service/exchange`, при запуске печатается строка `Обмен файлами с 1С: <путь>`):

| Папка | Кто пишет | Что лежит |
|---|---|---|
| `inbox/` | 1С | запросы `<ид>.json` и документы `<ид>.pdf`, `.png`, `.jpg`, `.jpeg`, `.xml` |
| `outbox/` | сервис | ответы `<ид>.json`; 1С читает и удаляет |
| `pending/` | сервис | `<ид>.txt` с id задания, пока документ обрабатывается |
| `rejected/` | сервис | файлы с недопустимым именем |

- **`<ид>`** — латиница, цифры, `_` и `-`, до 64 символов (например, GUID без дефисов). Из него строится имя ответа. Файл с другим именем переносится в `rejected/` без ответа.
- **Запрос** `inbox/<ид>.json` в UTF-8 (BOM допускается): `{"method": "health"}` → в `outbox/<ид>.json` тот же JSON, что у `GET /v1/health`.
- **Документ** `inbox/<ид>.pdf` и т. п. ставится в очередь как `POST /v1/extract` с `mode = auto`. Когда задание выполнено или завершилось ошибкой, в `outbox/<ид>.json` появляется тот же JSON, что у `GET /v1/jobs/{id}` (статус `done` или `failed`). Промежуточных ответов нет. Связь «ид → задание» хранится в `pending/` и переживает перезапуск сервиса.
- **Ошибка** (неизвестный метод, не JSON, не тот тип файла, очередь заполнена) — `{"detail": "текст"}` в `outbox/<ид>.json`.
- **Без половинчатых файлов:** 1С пишет файл под расширением `.tmp` и затем переименовывает его. Файлы с другими расширениями сервис не трогает. Ответ сервис пишет так же (`<ид>.json.tmp` → `<ид>.json`), поэтому 1С никогда не прочитает половину.
- Отключить: `uv run docai serve --no-exchange`; другая папка: `--exchange-dir D:\obmen`.

```bsl
// 1С: запрос состояния через файлы (полный пример — onec/src/.../Module.bsl)
Ид = СтрЗаменить(Строка(Новый УникальныйИдентификатор), "-", "");
Запись = Новый ЗаписьТекста(Папка + "\inbox\" + Ид + ".tmp", КодировкаТекста.UTF8);
Запись.Записать("{""method"": ""health""}");
Запись.Закрыть();
ПереместитьФайл(Папка + "\inbox\" + Ид + ".tmp", Папка + "\inbox\" + Ид + ".json");
// ... раз в секунду проверять, появился ли Папка + "\outbox\" + Ид + ".json"
```

## Безопасность

- Только `127.0.0.1`: адрес в команде запуска не настраивается; проверяется заголовок `Host` (защита от DNS rebinding со страниц в браузере).
- Файл до 20 МБ: слишком большой запрос обрывается, не дожидаясь конца загрузки (413).
- Тип проверяется по первым байтам: PDF, PNG, JPEG, XML. Имя файла на диск не попадает, хранится под `source.<расширение>`; исходное имя сохраняется только как метка.
- Аутентификации нет: сервис рассчитан на один компьютер. Документы и правки лежат в `data/service/` открытыми файлами.

## Запуск

```powershell
# Проверит Ollama и поднимет сервис на 127.0.0.1:8000
.\scripts\start.ps1

# То же без проверок
uv run docai serve --port 8000
```

Проверка: открыть `http://127.0.0.1:8000/docs`, в `POST /v1/extract` нажать *Try it out*, выбрать PDF, затем подставить полученный `id` в `GET /v1/jobs/{id}`.

## Пример для 1С

Рабочая обработка, проверенная на учебной платформе 8.3.8, — `onec/` (DocaiCheck: `GET /v1/health` по HTTP и через файлы; сборка и запуск — `onec/README.md`). Ниже — набросок опроса задания:

```bsl
Соединение = Новый HTTPСоединение("127.0.0.1", 8000);
Запрос = Новый HTTPЗапрос("/v1/jobs/" + Идентификатор);
Ответ = Соединение.Получить(Запрос);
Чтение = Новый ЧтениеJSON;
Чтение.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку("UTF-8"));
Задание = ПрочитатьJSON(Чтение, Ложь);   // структура: Задание.status, Задание.fields, …
Если Задание.status = "done" Тогда
    Сумма = Число(Задание.lines[0].amount_with_vat);   // числа приходят строками с точкой
КонецЕсли;
```

`ПрочитатьJSON` и строковые функции 8.3.6+ (`СтрСоединить`, `СтрНайти` и др.) недоступны, если конфигурация работает в режиме совместимости 8.3.5 и ниже. Тогда JSON разбирают объектом `ЧтениеJSON` по шагам, как в `onec/` (D54).

Для загрузки файла нужно тело `multipart/form-data`; его собирают вручную (граница, заголовок `Content-Disposition: form-data; name="file"; filename="..."`, двоичные данные файла).
