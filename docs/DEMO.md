# Демонстрация: от файла до документа в 1С (около 3 минут)

Сценарий для защиты и видео. Идёт по шагам: что открыть, что нажать, что сказать. Все пути — от корня репозитория `C:\DOCai-1c`. Команды — для PowerShell.

## За 10 минут до начала (подготовка, в кадр не попадает)

1. **Закройте** 1С с базой, которую будете показывать (учебная версия пускает один сеанс на базу). Показывайте на **копии** базы (`docai_bp_demo_test`), а не на рабочей: в ней создаётся документ.
2. Поднимите окружение и прогрейте модель. Скрипт запустит Ollama и сервис, если они не запущены, прогонит 10 документов и **оставит всё работать**:

   ```powershell
   .\scripts\demo_e2e.ps1 -KeepRunning
   ```

   В конце должно быть `Обработано: 10 из 10`. Это занимает 2–3 минуты (медиана 13 с на документ). Первая модельная загрузка медленнее, поэтому прогрев нужен до записи.
3. Если нет `build\DocaiLoad.epf`, соберите обработку (около минуты; база `docai_bp_empty` не должна быть открыта):

   ```powershell
   .\scripts\onec_build.ps1 -Name DocaiLoad
   ```

4. Запустите 1С, выберите **копию демо-базы** (`docai_bp_demo_test`), войдите как **АбрамовГС (директор)** (пароля нет). Если спросит про перемещение базы — «Это копия информационной базы».
5. **Файл → Открыть...** → `C:\DOCai-1c\build\DocaiLoad.epf` → в «Предупреждении безопасности» **«Да»**. Откроется окно «Загрузка первичных документов (ИИ)». В строке **«Сервис»** должно быть «готов: модель qwen3.5:2b-q4_K_M».
6. Файлы для показа уже лежат в `data\demo\`:
   - `data\demo\1c\upd_edo_ZHI301.xml` — УПД из ЭДО, поставщик и договор есть в базе;
   - `data\demo\09_upd_scan.jpg` — скан УПД.
7. Подготовьте окно терминала с каталогом проекта. В файловом диалоге 1С путь печатается в поле «Имя файла».

Номер ЖИ-301 в копии демо-базы должен быть свободен. Если на шаге 4 сценария появится «Документ уже есть в 1С», значит, вы уже показывали этот файл: откройте его через «Журнал» либо сгенерируйте новый номер (`build\p17\json\t1.json`, поле `number`, затем `uv run docai edo export --in build\p17\json --out build\p17\xml`).

## Сценарий

### 0:00–0:25. Что это и что запущено

**Покажите** терминал и выполните:

```powershell
.\scripts\demo_e2e.ps1 -Only xml
```

**Скажите:** «Всё работает локально на ноутбуке: Ollama, сервис, 1С. Скрипт проверил, что модель и сервис живы, и обработал документы через тот же API, который использует 1С». Видно строку «Здоровье: статус ok», «Обработано: 2 из 2», секунды на документ.

(Для видео можно вместо этого показать заранее записанный полный вывод `demo_e2e.ps1` на 10 документах: таблица видов, путей и времени.)

### 0:25–1:35. Документ из ЭДО: файл → документ в 1С

1. Окно 1С, кнопка **«Загрузить файлы...»** → в поле «Имя файла» введите `C:\DOCai-1c\data\demo\1c\upd_edo_ZHI301.xml` → **Открыть**. Новая строка добавляется в **конец списка**; прокрутите вниз.
2. Состояние за секунду-две: «Готово: можно загружать». **Скажите:** «XML по формату ФНС разбирается без нейросети, ошибок нет».
3. **Двойной щелчок** по строке. Откроется форма проверки: вверху «УПД (статус 1) № ЖИ-301», блок **«Справочники 1С»**: организация найдена по ИНН покупателя, контрагент — по ИНН и КПП, договор.
4. Вкладка **«Товары и услуги (3)»**. У строки 2 «Онлайн касса Эвотор 7.2» ячейка «Номенклатура 1С» жёлтая: «похожих: 1». **Щёлкните** по ячейке, нажмите **«Показать все»**, выберите **«Онлайн-касса (сходство 67%)»**. Ячейка станет зелёной «выбрана из похожих». **Скажите:** «Не угадал — предложил, решает человек».
5. Кнопка **«Создать документ в 1С»** → вопрос «Создать в 1С «Поступление (акты, накладные, УПД)»…» → **«Да»**. Через несколько секунд откроется **«Поступление товаров: Накладная, УПД 0000-0000NN»**: три строки, ставка 20%, всего 48 301,80, НДС 8 050,30, внизу ссылка «УПД: ЖИ-301 … код вида операции 01» (счёт-фактура). **Скажите:** «Документ создан непроведённым: проводит бухгалтер».

### 1:35–2:30. Скан: модель не уверена, человек исправляет

1. Закройте документ. В главном окне **«Загрузить файлы...»** → `C:\DOCai-1c\data\demo\09_upd_scan.jpg` → Открыть. Статус «Распознаётся...» около 15 секунд. **Скажите** пока идёт: «Скан читает мультимодальная модель 2B на видеокарте с 4 ГБ, документ распознаётся 13–20 секунд».
2. Двойной щелчок по строке «Готово: нужна проверка». Слева страница документа, справа реквизиты: **жёлтые** — модель не уверена, **красные** — значение не прошло проверку (в колонке «Замечание» причина).
3. На вкладке **«Реквизиты»** найдите красные «Продавец: КПП» и «Покупатель: КПП»: модель записала туда ИНН. По картинке слева исправьте: продавец `534150305`, покупатель `782543403` (двойной щелчок по ячейке, ввод, Enter). Ячейки станут зелёными, в «Замечании» — что было.
4. Нажмите **«Готово»**. **Скажите:** «Правки ушли в сервис — это будущие данные для дообучения. В списке: «Проверено: исправлено N из M значений».» (Создавать документ для этого поставщика здесь не нужно: кнопки «Создать...» у контрагента и договора делают это тем же способом.)

### 2:30–2:50. Журнал и защита от дубля

1. Кнопка **«Журнал»** — все документы с меткой `[docai]`: сумма, проведён ли, из какого файла.
2. Вернитесь в окно проверки УПД ЖИ-301 (двойной щелчок по его строке) и снова **«Создать документ в 1С»**: «Документ уже есть в 1С… Повторно он не создаётся». **Скажите:** «Второй раз не создаст».

### 2:50–3:10. Что бывает, если сервис не запущен (по желанию)

1. В терминале остановите сервис: Ctrl+C в окне, где он запущен (если запускали `demo_e2e.ps1 -KeepRunning`, сервис работает в фоне: закройте его через «Диспетчер задач» → процесс `python.exe` с `docai`, либо пропустите этот шаг).
2. В 1С нажмите **«Проверить связь»** (внизу, «Настройки сервиса») или **«Загрузить файлы...»**: в строке «Сервис» появится «Сервис docai не отвечает по адресу http://127.0.0.1:8000. Запущен ли он? В PowerShell из папки проекта: .\scripts\start.ps1». 1С не падает, файл получает статус «Не отправлен».
3. Запустите сервис снова `.\scripts\start.ps1`. **Скажите:** «Если упала Ollama, сервис это покажет, а XML продолжит обрабатываться».

## Что может пойти не так

| Что видите | Что делать |
|---|---|
| «Сервис docai не отвечает» | `.\scripts\start.ps1` или `.\scripts\demo_e2e.ps1 -KeepRunning` |
| «работает не полностью: Ollama недоступна» | запустить Ollama (приложение или `ollama serve`); XML работает и без неё |
| Сканы распознаются дольше минуты | первая загрузка модели в видеопамять; прогрейте её шагом 2 подготовки |
| «Документ уже есть в 1С» | показывали раньше: откройте через «Журнал» или смените номер (см. подготовку) |
| 1С не пускает в базу | в учебной версии один сеанс на базу: закройте другой сеанс или Конфигуратор |
| Документ со ставкой 22% не создаётся | учебная Бухгалтерия 3.0.111 не знает 22% (D56); для показа берите документы до 2026 года (в демо-наборе они такие) |
| Модель назвала УПД счётом (`07_upd_clean.png`) | известная ошибка пути vision (см. `reports/2026-11-19_p17_e2e/report.md`): в демонстрацию этот файл не берите |

## Как провести репетицию с секундомером

Заполните таблицу в `reports/2026-11-19_p17_e2e/report.md` (раздел «Таблица для секундомера»): время от «Открыть» в файловом диалоге до готовой строки, время проверки и правок, время от «Создать документ в 1С» до открытого документа. Эти цифры заменят оценки.
