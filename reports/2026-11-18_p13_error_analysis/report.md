# P13: анализ ошибок конфигурации по умолчанию

**Что анализируется.** Последний отчёт для конфигурации по умолчанию (D48) — `reports/2026-11-18_p12_matrix`, ячейка `q2q4__text`: Qwen3.5-2B Q4_K_M, путь text (текстовый слой PDF), промпт `text_v2`, даты как напечатаны, постобработка P10. 150 документов сплита test, ответы модели взяты из кэша `data/experiments/eval/p12_matrix/q2q4__text/`, ничего не перезапускалось.

**Воспроизвести:**

```powershell
uv run docai eval-errors --matrix configs/eval/p12_matrix.yaml --cell q2q4__text --docs 150 --out reports/2026-11-18_p13_error_analysis
```

Результат — `errors.json` (все счётчики и примеры) и `errors.md` (таблицы). Правила отнесения к причинам — `src/docai/eval/errors.py` (D49).

## Как считается

- Каждое неверное значение после постобработки получает одну причину: поле шапки, ячейку сопоставленной строки, расхождение числа строк. Причины проверяются по порядку, побеждает первая подходящая. Для причин, связанных с текстом, используется текст, который видела модель.
- Если постобработка заменила значение (автоисправление суммы), причина ищется по ответу модели: исправление выведено из неверного ответа. Если модель ответила верно, а постобработка испортила ответ, причина — `autofix`.
- **Блокирующие** ошибки — ошибки в обязательных полях: из-за них документ нельзя загружать без правок (D44).
- **Потолок** — сколько непрошедших документов прошли бы, если бы исчезли все блокирующие ошибки этой причины и только они. Это верхняя оценка пользы исправления, по ней выбирались изменения.

**По типам документов.** Хуже всего УПД: без правок 6 из 47; у 31 из 47 тип прочитан как счёт-фактура. Шапка УПД начинается со строки «Счёт-фактура № …», а признак УПД («Статус: 1») теряется. У счетов на оплату ошибки в банке: в таблице реквизитов оба счёта подписаны «Сч. №», модель кладёт корреспондентский счёт в расчётный, а корреспондентский оставляет пустым (у 13 счетов одновременно). У УПД, счетов-фактур и ТОРГ-12 наименование, адрес и ИНН/КПП стороны идут в одной строке: модель берёт индекс из начала адреса за ИНН, ИНН за КПП, а адрес пишет без индекса. Сдвиг граф бывает в широкой таблице УПД (16 граф, двухэтажная шапка, строка номеров граф «А | Б | 1 | 1а») и в акте (графы «Кол-во | Ед. изм. | Цена» без кода ОКЕИ: модель пишет количество в код ОКЕИ, а цену — в количество).

## Предложенные изменения (до трёх, по ожидаемому эффекту)

Потолки посчитаны на этих же 150 документах. Для пары изменений A + C потолок 53 документа, для всех трёх — 65 (из 91 непрошедшего). Изменения проверялись **только на val** (150 документов, `configs/eval/p13_val_*.yaml`) по одному, каждое поверх уже принятых. Test использовался только для финального замера на других 154 документах (те 150, по которым сделан анализ, исключены: `configs/eval/p13_test_seen_ids.txt`).

1. **E1 — правило постобработки: тип документа и статус УПД по заголовку текста** (`postprocess.doc_type_by_title`, D50).
   - *Гипотеза:* тип УПД однозначно виден в заголовке («УПД», «Универсальный передаточный документ», «Статус: 1|2» рядом со «Счёт-фактура»). Правило уберёт причину «тип» почти полностью: доля без правок вырастет на ≥ 8 п.п. (потолок +13 п.п.), и упадёт доля «молча загружен с ошибкой», которую сейчас дают именно УПД, прочитанные как счёт-фактура.
   - *Проверка:* модель не перезапускается, правило применяется к кэшу базы val. Парное сравнение с `p13_val_base`: бутстреп разности и Макнемар по «без правок». Отдельно — точность правила на 300 документах train (297 верно, 3 без изменений, 0 неверно).
2. **E2 — промпт `text_v3`** (D51): правила для строки «наименование, адрес, ИНН/КПП» (ИНН — 10 или 12 цифр, шестизначное число в начале адреса — индекс, часть адреса), для счетов банка (к/с начинается с 30101, р/с — нет; оба бывают подписаны «Сч. №»), запрет пометок «(2а)»; пример ИНН/КПП без настоящих чисел.
   - *Гипотеза:* причины «соседнее поле», «адрес без индекса», «поле не найдено» (к/с) и утечка примера сократятся минимум вдвое, доля без правок вырастет на ≥ 8 п.п. (потолок +20 п.п.).
   - *Проверка:* новый прогон модели на тех же 150 документах val, парное сравнение с принятой конфигурацией после E1.
3. **E3 — предобработка текста: таблица позиций построчно «графа: значение»** (`text_tables: labeled`, D52). Двухэтажная шапка склеивается в подпись графы, строка номеров граф и пустые ячейки («--») выбрасываются.
   - *Гипотеза:* модели не придётся считать столбцы, поэтому исчезнет сдвиг граф в УПД и актах. F1 ячеек вырастет, доля без правок — на ≥ 4 п.п. (потолок одного изменения +5 п.п.).
   - *Проверка:* новый прогон модели на val, парное сравнение с лучшей принятой конфигурацией. Дополнительно — рост длины промпта и секунд на страницу.

Не взяты в работу (меньше эффект или нужен другой инструмент): потеря дробной части (4 документа: грамматика JSON-числа обрывает «12,3» на запятой; лечится числами «как напечатаны» по образцу D47); выдуманные суммы ТОРГ-12 — почти все следствие той же потери дробной части; разбиение на страницы или области (ошибки не связаны с длиной: 87% документов одностраничные); предобработка изображения (путь text картинок не использует).
